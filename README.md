## Лабораторная работа №2

### Создание процессов и взаимодействие через каналы

ФИО: Оганнисян Айк Арменович

Группа: М8О-201БВ-25

Вариант: 19

### Цель работы

Приобрести практические навыки управления процессами в ОС Linux: создания
дочерних процессов, запуска в них других программ, обмена данными между
процессами через неименованные каналы, перенаправления стандартных потоков
ввода-вывода и освобождения ресурсов операционной системы.

### Постановка задачи

Разработать программу на языке Си. Родительский процесс создаёт два дочерних
процесса. Первой строкой пользователь вводит имя файла, который будет открыт
на запись для первого ребёнка, второй строкой аналогично для второго.
Родительский и дочерние процессы должны быть представлены разными программами.

Родитель принимает от пользователя строки произвольной длины и пересылает их
в `pipe1` или в `pipe2` по правилу фильтрации: с вероятностью 80% строка
отправляется в `pipe1` (первому ребёнку), иначе в `pipe2` (второму ребёнку).
Дочерние процессы удаляют из строк все гласные и пишут результат в стандартный
вывод, который перенаправлен в их файл.

Необходимо обрабатывать ошибки системных вызовов, закрывать дескрипторы,
освобождать динамическую память и дожидаться завершения обоих дочерних процессов.

### Алгоритм решения

1. Родитель читает имена двух файлов, открывает их на запись и создаёт
   два канала.
2. Родитель создаёт двух потомков через `fork`. В каждом потомке через `dup2`
   стандартный ввод перенаправляется на его канал, а стандартный вывод
   в его файл, лишние дескрипторы закрываются, и через `execl` запускается
   программа `child`.
3. Родитель читает строки пользователя и отправляет каждую в `pipe1`
   с вероятностью 80%, иначе в `pipe2`.
4. Потомок читает строки из стандартного ввода, удаляет гласные и пишет
   результат в стандартный вывод, то есть в свой файл.
5. После окончания ввода родитель закрывает каналы, потомки получают
   конец данных и завершаются, а родитель дожидается их через `waitpid`.

Используются две исполняемые программы: `parent` и `child`, исходные файлы
`parent.c` и `child.c`. Во время работы существуют три процесса: один
родительский и два дочерних. Каждый дочерний процесс создаётся через `fork`,
после чего в нём через `execl` запускается программа `child`. Имя ребёнка
(`child1` или `child2`) передаётся как `argv[0]` и используется в сообщениях.
Файлы открывает только родитель; программа `child` файлы не открывает
и работает через уже перенаправленные `stdin` и `stdout`.

### Ввод и вывод программы

Ввод: две строки с именами выходных файлов, затем строки текста. Длина строк
не ограничена фиксированным буфером: `getline` сама увеличивает буфер.
Завершение ввода `Ctrl+D` на пустой строке.

Вывод: обработанные строки в двух файлах. В первый файл попадает примерно 80%
строк, во второй примерно 20%; распределение случайное и меняется
от запуска к запуску. Удаляются английские гласные `a e i o u y`
в обоих регистрах. Русские буквы, цифры, пробелы и знаки препинания
сохраняются. В терминал выводятся сообщения с PID родителя и детей:
создание процессов, выбранный канал и запись каждой строки в файл.

Сборка и запуск:

```bash
make
./parent
```

Удаление собранных файлов: `make clean`.

### Обработка ошибок

- Большинство системных вызовов проверяется, при ошибке выводится сообщение
  через `perror` или `fprintf(stderr, ...)`.
- Пустое имя файла или отсутствие ввода приводят к завершению с кодом 1.
- Если программа `child` не найдена, `execl` возвращает ошибку, дочерний
  процесс выводит `execl: No such file or directory` и завершается,
  родитель дожидается его через `waitpid`.
- Если дочерний процесс завершается во время работы, запись в его канал
  возвращает `EPIPE` (`write: Broken pipe`), и родитель переходит в блок
  очистки: закрывает каналы и дожидается обоих детей.
- Перед каждым `fork` вызывается `fflush(stdout)`, чтобы непустой буфер
  вывода не скопировался в дочерний процесс и не был выведен повторно.
